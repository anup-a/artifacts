Publish a page. Get a link.

A Markdown file or a folder of static HTML goes in; a versioned URL comes out. Send it to anyone, collect comments on the page itself, and publish again from the same directory to update it in place.

npx byagent publish ./report.md

Node 18 or newer. No build step, no config file, and readers need no account.

Quickstart

  1. Create a key

    {{if $d.SignIn}}Sign in at {{$d.KeysURL}} and create a named key. The full key is shown once.{{else}}This server has no sign-in configured, so keys come from its ADMIN_TOKEN.{{end}}

  2. Point the CLI at this server

    echo "$KEY" | npx byagent login --api {{$d.APIOrigin}}

    Writes ~/.artifacts/config.json. ARTIFACTS_API and ARTIFACTS_TOKEN override it in CI.

  3. Publish

    npx byagent publish ./site --project "Docs" --tag api

    The directory remembers its artifact in .artifacts.json, so publishing again keeps the same URL. A new directory is a new link.

What the link gives you

Versions, and a way back
Every publish keeps the previous ones. Roll back with byagent rollback <id> 3 or one click in the dashboard.
Comments on the page
A reader selects the line they mean and leaves a thread on it. Reply and resolve from the dashboard or with byagent reply and byagent resolve.
Private, or private with a code
--private keeps it inside your workspace. byagent share <id> issues six digits that open that one page for someone outside; --off withdraws them.
Markdown, already styled
A .md file is rendered on publish: light and dark, heading anchors, a contents list, GFM tables and highlighted code. The first H1 becomes the title.
Projects, tags and covers
--project and --tag group your artifacts and filter the dashboard. Each page gets a generated cover, used as its og:image in link previews.
Scriptable output
Every command takes --json and prints exactly one object on stdout. Errors print one object on stderr and exit non-zero.

CLI

npm install -g byagent, or npx byagent <command>. Full flags: byagent <command> --help.

publish <dir|file>Uploads what changed and publishes a version. --title --project --tag --private --public --no-comments --cover
get <id>URL, title, current version, open comments, project and tags
listEverything in the workspace, filterable by --project or --end-user
share <id>Issues or rotates the six-digit code for a private page; --off withdraws it
versions <id>Version history with per-version comment counts
rollback <id> <n>Republishes an old version as the newest one
comments <id>Threads with their anchor status; --open, --all, --since
reply <id> <thread>Posts an owner reply on a thread
resolve <id> <thread>Marks a thread resolved
delete <id>Soft-deletes the artifact; the URL stops working
whoamiCurrent workspace and key
portal-link <user>Seven-day read-only customer portal, integrator workspaces only

For agents

byagent exists so an agent can hand back a URL instead of a file path or a wall of chat markdown. One command, one JSON object, and the page is live where a human can open it, comment on it and come back to it.

This server serves the skill it expects agents to follow: {{$d.SkillURL}}. Save it as SKILL.md in your agent's skills directory.

Self-host

One Go binary with SQLite or Postgres, local disk or S3. Published pages must not share an origin with the dashboard, so set PUBLIC_SHARE_ORIGIN and PUBLIC_API_ORIGIN to two hosts — here, {{$d.ShareHost}} and {{$d.APIHost}}.
